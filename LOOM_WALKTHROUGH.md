# 360Ghar - Loom Walkthrough Script (2-3 minutes)

**Goal**: Show the complete feature set and how thoughtfully the AI works.

---

## 📹 Loom Video Structure (2-3 min)

### Scene 1: Introduction (15 sec)
**Camera**: Full screen showing the app  
**Narration**: "Hi, this is my 360Ghar property search assistant. It's an AI-powered interface that understands what you're looking for in plain English and finds the perfect property for you."

**Show**: 
- Header with logo and subtitle
- Clean search interface
- Highlight voice button

---

### Scene 2: Text Search Demo (40 sec)

**Narration**: "Let me start with a natural language search. I'll type: '2BHK in Sector 50 under 80 lakhs, good sunlight, near school.'"

**Actions**:
1. Click on search input
2. Type the query slowly (so viewer can read it)
3. Click "Search" button
4. Show loading state with spinner briefly
5. Properties appear with smooth animation

**Narration while results load**: "The app is sending this to an LLM via OpenRouter. The model parses the natural language into structured filters — location, BHK type, budget, amenities, preferences."

**Show results**:
- Property cards appear
- Point out match badges: "See these badges? 'Matches 2BHK · Within budget · Good natural light' — that's the AI explaining why each property matches your query. Not just filtering, but reasoning."
- Highlight the color coding and polish

---

### Scene 3: Voice Input Demo (20 sec)

**Narration**: "Now let's try voice input. I'll click the microphone button and speak naturally."

**Actions**:
1. Click voice button (🎙️)
2. Wait for "Listening..." state to appear
3. Speak naturally: "I want a 3BHK near schools, good market access, around 1 crore"
4. Wait for transcription to fill search box
5. Automatically trigger search (or click search)
6. Show new results load

**Narration**: "The voice input captures natural speech and works just like text. Great for hands-free browsing."

---

### Scene 4: Property Detail & AI Summary (40 sec)

**Narration**: "Now let's click on one of these properties to see the detailed summary."

**Actions**:
1. Click on the first property card
2. Modal opens with:
   - Large property image
   - All details (BHK, price, location, area)
   - Amenities list
3. Show the "Why This Property?" section loading
4. **Wait for AI-generated summary to appear** (this is key!)

**Narration while summary loads**: "This summary is generated by the LLM in real-time. It connects back to your original query — notice how it mentions the specific things you asked for. This is what makes it feel personalized, not generic."

**Once summary appears**, read it aloud or highlight the personalization:
- "It references the budget you mentioned"
- "It connects to the sunlight preference"
- "It feels like the app actually understands what you need"

**Then close modal** (click X button)

---

### Scene 5: Property Card Interaction (20 sec)

**Narration**: "Notice the UI polish. When I hover over properties, they animate. The cards have thoughtful spacing and colors. Every interaction feels intentional."

**Actions**:
1. Hover over 2-3 property cards slowly
2. Show the lift/shadow animation
3. Point out the badge design
4. Show how price stands out in the accent color

---

### Scene 6: Different Query (20 sec)

**Narration**: "Let me try a different, more vague query to show robustness. 'Affordable family home with green space and good schools.'"

**Actions**:
1. Clear search (or type new query)
2. Type the new query
3. Click search
4. Show different results this time
5. Different match badges appear

**Narration**: "The model handles vague language too. It interprets 'affordable' as lower price, 'family home' as 2-3BHK, and prioritizes properties near schools and green spaces."

---

### Scene 7: Code Quality Mention (15 sec)

**Narration**: "The code is clean and straightforward. No over-engineering. I'm using React hooks for state management, and all the styling is CSS — no bloated UI libraries."

**Actions** (Optional, if you have time):
- Quickly show GitHub repo link
- Maybe a glimpse of component structure in README

---

### Scene 8: Closing (10 sec)

**Narration**: "This is a complete, polished prototype that demonstrates AI integration, product thinking, and clean code. Every feature serves a purpose. Ready to ship."

**Actions**:
- Do one more successful search flow end-to-end (text → results → detail → summary)
- End on a satisfied note

## 🎬 Production Tips for Loom

### Audio
- **Speak clearly** and at a steady pace
- **Add pauses** before clicking to let LLM API respond
- **Don't rush**: 2-3 minutes is plenty; slower is better than cramped
- Use a quiet room (no background noise)

### Visual
- **Full screen or wide window** (so properties are visible)
- Zoom in if needed (Cmd/Ctrl + Mouse Wheel)
- **Slow your mouse movements** — rushing clicks looks unprofessional
- Highlight important UI elements by hovering or circling

### Flow
1. **Intro** (who, what, why)
2. **Features** (text search → voice search → detail modal → AI summary)
3. **Polish** (hover effects, animations)
4. **Close** (complete flow demo)

### Timing
- Intro: 10-15 sec
- Text search: 40-50 sec
- Voice search: 20 sec
- Property detail: 40 sec
- Interactions: 20 sec
- Different query: 20 sec
- Closing: 10-15 sec
- **Total**: 2:30-3:00

## 🚨 Common Loom Mistakes to Avoid

❌ **Don't**:
- Rush through features
- Have errors in the demo (test beforehand!)
- Forget to show the AI summary generation
- Talk too fast or mumble
- Show boring parts (minimize scrolling, jumping around)
- Have slow API responses visible (test API connectivity first)

✅ **Do**:
- Practice your script 1-2 times first
- Test the app thoroughly before recording
- Speak clearly and confidently
- Point out the intentional design choices
- Show complete flows (not just fragments)
- Pause before API calls so they don't look frozen
